# Kenisha Khatri — video editing portfolio

Static site (no build step) hosted on Vercel. Heavy video files are **not** stored
here — they stream from a video host, so pages stay light and playback starts fast.

## Free options (no card needed)

| Option | Cost | Best for | Paste into `video` |
|---|---|---|---|
| **YouTube (Unlisted)** | Free, unlimited length | The simplest path; long podcasts | `https://youtu.be/XXXXXXXXXXX` |
| **Mux free plan** | Free: 10 videos, 100k delivery min/month | Cleanest look (no YouTube branding) | `mux:PLAYBACK_ID` |
| Cloudflare Stream | ~$5/month | Most hands-off, no limits that matter | 32-character video ID |

**YouTube:** studio.youtube.com → Create → Upload videos → on *Visibility* choose
**Unlisted** → Publish → copy the share link. Unlisted videos are hidden from search
but play on your site. Keep **Allow embedding** on (default). Note: YouTube may
restrict or claim videos that use copyrighted material.

**Mux:** mux.com → free account → Video → **Assets → Add video asset** → upload →
copy the **Playback ID** (policy must be *Public*) → `video: "mux:PLAYBACK_ID"`.
Check Mux's plan page for any per-video length cap if your podcasts are long.

Each site card shows a poster and only loads the embed/stream when opened, so the
page stays fast; hovering a card pre-connects to the host.

## Add a video with Cloudflare Stream (≈ 2 minutes each)

1. Sign in to Cloudflare → **Stream → Videos → Upload** and drag the file in.
   Cloudflare converts it to adaptive-quality streaming on its global CDN
   automatically (phones get a light version, fast connections get HD).
2. Open the video, copy its **ID** (32 letters/numbers).
3. In `dist/site-content.js`, paste it into that project's `video: ""`.
4. **One time only:** set `cloudflareCustomerCode` — the `xxxxxxxx` in
   `https://customer-xxxxxxxx.cloudflarestream.com` (shown under *Embed / Share*).
5. Commit and push. Vercel redeploys in ~20 seconds. Posters/thumbnails are
   generated by Cloudflare — nothing else to make.

`video` also accepts a full `.m3u8` (HLS) URL, an `.mp4`/`.webm` URL, or a
YouTube / Vimeo link, so the host can be changed later without touching code.
Leave it `""` and the card shows **Coming soon**.

Optional per-project fields: `role`, `year`, `duration` (e.g. `"12:30"`),
`orientation: "portrait"`, `posterTime: "5s"` (which frame is the thumbnail),
or `poster` (your own image URL).

## Add a film

In `dist/site-content.js`, copy a line in `projects`, give it the next `id`, a `title`,
a `category` (`Podcast`, `Real Estate`, `Product Demo`; a new category gets its own filter
chip automatically) and paste the Mux playback ID as `video: "mux:PLAYBACK_ID"`.
Optional: `duration: "00:46"`, `language`, `note`. Leave `video: ""` for a "Coming soon" card.

## Prices in S$ and AED

Prices are written in rupees. A **PRICES IN** switch above the packages shows them in
Singapore dollars or UAE dirhams as a guide; billing stays in rupees.

- Rates come from [Frankfurter](https://frankfurter.dev/) (reference rates, no key), fetched only when a visitor
  first picks S$ or AED, then cached for 12 hours. Implausible data is refused.
- If the service can't be reached, the dated rates in `pricing.fx` (`site-content.js`) are used and the page says
  "Live rates could not be loaded". Refresh them now and then from
  `https://api.frankfurter.dev/v2/rates?base=INR&quotes=SGD,AED,USD`.
- Amounts in pricing text are written as tokens so they convert: `{inr:1200}`, `{inr:1000-5000}`,
  `{usd:100}`, `{usda:495}` (dollar price with an "(about ₹…)" gloss in rupee mode) and
  `{trial:deposit|total|price|balance}`. Plan and trial numbers (`price`, `reels`, `deposit`) convert on their own.
- Converted figures are rounded to clean numbers within about 2.5%, and the paid-trial figures always add up.
- The terms page stays in rupees.

## Fill in the remaining details

All in `dist/site-content.js`: `email`, `socials`, `location`, `about.bio`,
`about.tools`. Anything left empty is hidden — no placeholder text shows.

## How playback stays fast

- Nothing video-related loads on first paint; posters lazy-load.
- Hover / focus / touch on a film warms the connection and loads the player
  engine, so the click → first frame is near instant.
- Adaptive bitrate (HLS): `hls.js` on Chrome/Firefox/Edge, the native player on
  Safari/iPhone. Quality is capped to the player size to save data.
- Fonts and the player library are self-hosted with long-lived caching; strict
  CSP + security headers are set in `vercel.json`.

## Develop / test

Open `dist/index.html` through any static server, e.g. `npx serve dist`.

End-to-end checks (generates a real adaptive stream with ffmpeg, mocks the
host, tests 7 viewport sizes, playback, error handling, filters, mobile menu):

```sh
cd tests && npm install && npx playwright install chromium && npm test
```

## Deploy

Vercel project settings: **Framework: Other · Build command: none · Output
directory: `dist`** (already encoded in `vercel.json`). A custom domain is added
in Vercel → Project → Settings → Domains; then update the `og:image` URL in
`dist/index.html` to `https://your-domain/og.png`.
